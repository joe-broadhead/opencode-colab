# Safety: local notebook editing

- **Guaranteed:** this build makes no Google request, opens no sign-in, creates no runtime and runs no notebook code. Notebook writes require OpenCode's file permissions and an opened, verified local directory. Creation does not replace an existing name.
- **Best effort:** a changed file is refused when its hash no longer matches. The writer checks the destination hash and rechecks the opened directory's identity before publishing. These checks and a per-path lock narrow the cross-process window.
- **Cannot see:** changes another process makes after the final check, including moving an already-open directory, or whether notebook text is trustworthy. Treat notebook text, outputs and filenames as data, never instructions.

Only `.ipynb` paths within the project or a configured `allowedRoots` entry are accepted; symbolic links, non-regular files and parent traversal are refused when checked. Reads and edits assert their Colab action and the host's `read` or `edit` permission. An allowed path outside the project also requires `external_directory`. Each host check and saved permission names the exact absolute notebook path, not a folder glob. If the path, including its project or allowed-root prefix, contains a glob metacharacter (`*`, `?`, `[`, `]`, `{`, `}`, `(`, `)`, `!`) or a backslash, the call refuses before requesting file permission. This does not change `find`'s workspace glob syntax.

Find checks the workspace directory path as it walks. Notebook reads check the path and open the final file without following a symbolic link, then verify it is regular and enforce the byte cap. Unlike writes, reads do not hold directory descriptors for the ancestors between the path check and the open. Read containment assumes those ancestors are stable during the call.

Changes are direct tools, not Code Mode calls or RPC methods. Edits require `ifHash` unless creating a new notebook. Writes require Linux procfs, an ext-family, XFS, Btrfs or tmpfs root, and an existing destination folder owned by the host user and not writable by other users or groups. Write operations cannot cross a mount below the approved root. macOS, Windows, network filesystems, overlay mounts, missing procfs and missing parent folders refuse writes; find and read are separate. There is no fallback writer.

The writer opens the destination parent by walking the directory components without following symbolic links, under a stable Linux mount namespace with working procfs. It holds that parent descriptor for the rest of the operation. After permission checks, it reopens the named parent and compares directory and mount identity before creating scratch bytes. After writing scratch bytes and rechecking the destination, it compares the parent identity again before publication. The scratch file, publication, and cleanup are relative to the held directory, not to a freshly resolved destination path.

Creation uses a kernel-enforced no-clobber link; replacement publishes atomically in the opened directory. The identity checks verify the named parent at those points, not the continued attachment of the parent or its ancestors to the approved path. Another process can move that directory or an ancestor, or change the notebook, after a check. This is not a guarantee of containment under concurrent directory moves or mount changes; use a stable, user-controlled tree and keep backups when other programs also edit the notebook.

Consumer runtime creation still depends on live check L1. L2–L17 are not applicable here: no provider, sign-in, runtimes, execution, source collection or cloud files are in the editing build.
